# API

FastAPI backend, run as the `api` package from the project root.

## Layout

```
api/
├── main.py                    # FastAPI app: settings, middleware, routers
├── core/
│   ├── config.py               # Settings (pydantic-settings, reads api/.env)
│   ├── database.py             # Async SQLAlchemy engine/session, declarative Base
│   └── dependencies.py         # FastAPI Depends() wiring (DB session -> service)
├── models/                     # SQLAlchemy ORM models
├── schemas/                    # Pydantic request/response models
├── repositories/               # Data-access layer (one repository per aggregate)
├── services/                   # Business logic, orchestrates repositories
├── routers/                    # FastAPI routers (HTTP layer only)
└── alembic/                    # Migration environment (async, autogenerate-enabled)
```

Request flow: `router` -> `service` -> `repository` -> `model`. Routers only handle
HTTP concerns (status codes, request/response schemas) and delegate everything else
to a service; services own transactions (`commit`/`rollback`); repositories only
know how to query/persist a single model.

## Setup

1. `uv sync` (from the project root) to install dependencies.
2. `cp api/.env.example api/.env` and set `DATABASE_URL` to your PostgreSQL instance.
3. `uv run alembic -c api/alembic.ini upgrade head` to create the schema.
4. `uv run uvicorn api.main:app --reload` to start the dev server.

## Adding a migration

After changing a model in `api/models/`, generate a migration against a running
database (autogenerate needs a live connection to diff against):

```bash
uv run alembic -c api/alembic.ini revision --autogenerate -m "describe the change"
uv run alembic -c api/alembic.ini upgrade head
```

Always review autogenerated migrations before running them — Alembic can miss
things like renamed columns or table-level constraints.
